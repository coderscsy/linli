# API 配置使用说明

适用：R10.7 中转 API 兼容更新（2008.2.7-linli.9），2026-09-14；程序版本仍为 2008.2.7。此前公开的 R10.6 安装包不包含本次 API 兼容升级。

说明修订日期：2026-09-14。统一称为“中转站”，以用户使用的 seekai.cc 为配置示例。

## 一、安装与保留数据

- 安装包：退出游戏，并从托盘完全退出 OliviaSoul；备份原安装目录的 `UserData` 后，运行 Setup.exe，选择原安装目录覆盖升级，无需先卸载。
- 便携包：完整解压到独立、可写的目录，运行其中的 OliviaSoul.exe。不要只复制 EXE，也不要从 ZIP 内直接运行。新目录不会自动读取另一安装目录的配置和数据。
- 包内不附带个人 API Key、模型配置、信件、记忆或曲库。普通升级保留同一安装目录中的 UserData。

## 二、最快配置步骤

1. 启动 OliviaSoul，打开「AI 模型」。
2. 中转站或本地推理服务选择「通用兼容 API（本地 / 中转）」。
3. 在对应配置区填写接口地址、鉴权方式、API Key 和模型名。
4. 模型名可以手填；也可点击「查询模型列表」，再从候选中选择。查询失败不妨碍手填后测试。
5. 点击「保存并测试通用模型」。检测成功才保存这次配置；失败保留之前已保存的配置。
6. 确认顶部选择的是该档案，点击「检测并设为当前模型」。保存一个尚未启用的档案，不等于切换当前模型。

测试会实际发送一条短请求，可能消耗服务商额度。不要连续反复点击。测试成功说明本次请求能完成，不保证长文本、其他模型或后续网络状态一定正常。

## 三、中转站配置（以 seekai.cc 为例）

| 项目 | 填写方法 |
| --- | --- |
| 接口地址 | 按该站公开文档的默认地址格式，示例为 `https://seekai.cc/v1`；控制台若提供专用线路，以控制台为准 |
| 鉴权方式 | Bearer API Key |
| API Key | 从 seekai.cc 控制台创建或复制调用密钥；只填密钥本身，不加 `Bearer ` 前缀，不填网页登录密码 |
| 模型名 | 填该账户获准使用的完整模型 ID，可手填或查询后选择，不要凭商品显示名称猜测 |

也可填完整端点 `https://seekai.cc/v1/chat/completions`，程序会避免重复拼接，但不会自动补上 `/v1`。若中转站提供的地址带有自定义前缀，请保留完整前缀。不要把密钥放入地址；带查询参数、账号密码或 `#` 片段的地址不受支持。

### 这些地址分别做什么？

| 地址 | 用途 | 用户需要怎么操作 |
| --- | --- | --- |
| [seekai.cc 首页](https://seekai.cc) | 登录中转站控制台，获取接口地址、API Key 和可用模型名 | 用浏览器打开并登录 |
| `https://seekai.cc/v1` | OliviaSoul 调用模型的基础地址示例 | 填入软件的“接口地址”；控制台提供其他线路时，以控制台为准 |
| [接口使用文档](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/api) | 查看接入方法的说明网页 | 需要时阅读，不填进软件的接口地址栏 |
| `https://seekai.cc/api/status` | 给程序读取的站点状态信息，浏览器里通常显示 JSON（类似代码的文字） | 不用访问、不用看懂，也不要填进软件；它不能用于调用模型 |

普通用户只需登录中转站，取得“接口地址、API Key、模型名”，按上面的步骤填写即可，无需自行搭建中转站。这里提供的是配置示例，尚未用该用户的 seekai.cc 密钥验证成功。

已有远程档案可以继续使用；自定义地址或模型时，在远程配置区启用「自定义模型与地址」。中转站优先使用通用档案，避免发送厂商专用参数。

## 四、本机或局域网服务（非中转站用户）

- 类型：通用兼容 API（本地 / 中转）。
- 地址示例：`http://127.0.0.1:8000/v1`，端口以你实际启动的服务为准。
- 鉴权：按服务设置选择；未启用鉴权时选择无需鉴权。
- 模型：该服务实际加载并对外提供的模型 ID。

需要自己先启动推理服务，OliviaSoul 不会自动启动本地模型。另一台电脑上的服务不能填写 127.0.0.1，应填写从这台 Windows 电脑能够访问的地址，并确认端口与访问权限；不要把无鉴权接口直接暴露到公网。

## 五、支持范围

- 支持 Chat Completions 兼容请求、普通 JSON 正文、text/output_text 分段正文。
- 请求 `stream:false`，也能处理上游仍返回的 SSE；空增量和独立用量尾包不会清空正文。
- 最终正文与 reasoning/thinking 分开判断；只有推理、明确截断、断流或错误对象不会当作成功回复。
- HTTP 400/422 明确拒绝 `max_tokens` 时，保持同一上限，改为 `max_completion_tokens` 重试一次；不会因此切换服务商。
- 模型列表查询是可选操作，不会覆盖已经手填的模型名。

不支持直接填写 Claude Messages、Responses、Gemini 原生接口、Azure 特殊路由、自定义鉴权请求头或只接受 `stream:true` 的服务。相应厂商的模型若由中转站提供 Chat Completions 兼容端点，可以通过该端点接入；这不等于原生直连。

## 六、常见问题

| 现象 | 检查内容 |
| --- | --- |
| 查询模型失败，但已有模型名 | 直接手填模型名后保存并测试；部分服务没有开放模型列表 |
| HTTP 401 / 403 | 密钥是否正确、过期，鉴权方式是否匹配，令牌是否允许访问 |
| HTTP 404 | 地址是否缺少 `/v1` 或代理前缀，端点和模型名是否存在 |
| HTTP 400 / 422 | 模型或参数是否被上游支持，是否误填了原生协议地址 |
| HTTP 429 | 限流或额度限制；查看服务商控制台，稍后再试 |
| HTTP 5xx | 中转站或上游服务异常；查看服务状态，必要时联系中转站客服 |
| 超时、连接失败 | 服务是否启动，地址和端口是否可达，代理、网络或防火墙是否阻断 |
| 没有有效文字 / 正文未完整生成 | 服务只返回推理、正文为空、被过滤或截断；检查模型输出与上游设置 |
| 中转站提示无可用渠道 / 额度不足 | 检查账户和密钥额度、模型权限；渠道异常请联系中转站客服 |
| 保存成功，但仍使用原来的模型 | 在顶部选中对应档案，点击「检测并设为当前模型」 |

## 七、隐私与验证说明

回信、记忆处理、AI 导入和转写文本整理可能向当前接口发送相关文本；请使用可信服务。费用与数据处理规则以所用服务为准。不要在截图、日志或公开反馈中提交密钥；反馈时只提供脱敏地址、模型名、错误码及复现步骤。

本轮已通过协议模拟、安装版设置页与 PowerShell 回信链路验证，并在维护者当前配置的兼容服务上完成两条短请求验证。没有逐一实测所有商业中转站，也没有完成原生多协议接入。
