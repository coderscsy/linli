# Olivia Soul

WinForms + WebView2 桌面宿主管理内置 Node 本机后端，默认监听 `127.0.0.1:27149`，可在基础设置中换端口，数据使用 `node:sqlite` 保存。启动时若系统缺少 WebView2 Runtime，会运行微软在线引导程序。

v18 Harness、SQLite 记忆投影、人设和发布接入契约见 [`V18_ENGINEERING.md`](V18_ENGINEERING.md)。

## 运行

在工作区根目录执行：

```powershell
.\start-olivia-local.ps1
```

脚本会启动桌面应用和内置服务。最小化或关闭窗口后应用会驻留系统托盘；托盘菜单可重新打开窗口、设置开机启动或退出。基础设置页也提供“开机自动启动”开关。启用或关闭自启时会弹出 Windows 管理员确认，并通过最高权限计划任务在登录时启动。停止应用：

```powershell
.\stop-olivia-local.ps1
```

首次挂载时，在基础设置的“服务挂载”中点击“选择 exe”，定位游戏目录中的启动程序。应用以 exe 所在目录为锚点自动识别版本和 `feapp.dat`，不保存写死的 Steam 路径。填写端口后点击“一键挂载服务”，应用会先关闭该目录下正在运行的游戏进程、复制原版备份，再同步切换客户端与本机服务端口；“恢复客户端”会先关闭游戏，再用这份备份覆盖客户端，本机服务继续运行。

确认导入记忆时，同一批往来会同步写入游戏信箱历史；导入信件不占用主动发信额度。升级前已经存在的记忆会在首次启动或登录时补入信箱，并按来信与回信内容去重。

“记忆”页分为“记忆管理”、“.soul导入”和“AI识别导入”。AI 识别只需粘贴往来全文，再依次识别、校验和确认；原文缺少日期时保持为空，不自动补日期。记忆管理从上到下按新至旧排列，可设置或清空日期、新建、上下移动或删除往来，并用来信与林离回信两个输入框逐封修改，修改后需点该封的确认按钮。

记忆标题右侧始终显示整理状态：整理中、整理完成、整理中断或整理失败。修改、移动或删除信件会立即中断当前整理，暂停一分钟后自动继续；也可点击状态条立即继续，待整理状态下发信同样会自动触发。重复提交由服务端互斥，避免并发整理覆盖档案。

每组往来按“来信正文 + 回信正文”的 MD5 和摘要 Prompt 版本缓存逐封摘要；正文或摘要规则任一变化都会失效重算。摘要必须区分“他声称”和“她明确承认”。缺失的逐封摘要最多五路并行整理。最近十封保留逐封摘要，更早的信滚动合并为最多 500 字的大总结。旧信未改动时只把原大总结和新进入旧区的信交给模型；旧信有修改、删除或换序时才重建大总结。

每次回信前，服务从 SQLite 冻结不可变历史快照。模型可在预检后按需请求关键词搜索、精确读取或相邻信件；本地控制层只返回预算内、带信件 ID 与哈希的原文，并保存审计包。摘要只用于导航，关系、称呼、亲密动作和共同事实必须由原文建立。

记忆管理通过原生路径选择窗口导出单个 `.soul` 文件，流式封装原文、逐封摘要、旧记忆合集和每封信附挂的本地 MP4 备份；无记忆时不会生成空文件。`.soul导入` 是覆盖式恢复，连续确认两次后会完整替换现有记忆与视频。原有 `olivia-soul.memory` v1 标准 JSON 接口仍保留兼容。

“视频转文字”页支持常见视频和音频格式。程序先用随包分发的 FFmpeg 提取 16 kHz 单声道音频，再由 whisper.cpp 在本机逐字转写，最后把纯文字交给 DeepSeek 修正错字、标点和分段。发布包内置并校验约 465 MiB 的 Whisper small 模型，首次转写不再下载；安装路径含中文时会把已校验模型复制到 ASCII 安全路径后使用。媒体文件不会上传给模型。任务全局串行，页面会持续显示模型准备、音频提取、语音识别和文字整理进度，可随时取消。

记忆页的“远端记忆”分页会读取官方游戏最近一次信箱列表请求的一次性请求头，官方游戏无需退出。请求头只保留在当前任务内存中，不写入日志或临时 JSON。任务分页拉取已完成的往来；视频回信会下载原始 MP4并复用本地转写管线，完成后覆盖导入当前本地记忆。

“调试”页的“显示摘要”开关可显示“旧记忆合集”；开启后，已经整理完成的逐封摘要显示在“记忆”页对应往来下方，未完成的摘要不会占位。该页还可调整最小回信延迟、恢复默认 300 秒，以及修改每日写信上限。上限为 `0` 时不限次数，设置范围为 `0–999`；“重置今天信件次数”只影响额度计算，不会删除信箱中的信。

基础设置可配置登录接口返回的用户名与 UID，默认分别为“用户”和 `5200`；设置会在客户端重新登录后生效。`gwToken` 只用于通过原生初始化。不会请求或缓存新的官方登录结果；实时聊天、语音等远端网关能力不保证可用。

回信默认在发信五分钟后开放；调试页可修改这个最小延迟。若模型届时仍未完成，则继续等待模型。一小时仍未完成、模型返回错误，或服务重启导致正在生成的 HTTP 请求丢失，信件都会进入失败状态且不占每日三封额度。

连续发信时后台会保留唤醒请求，并严格串行处理：上一封完成回信、归档和记忆整理后，才开始生成下一封。启动新版时也会自动补写上一版已经生成回信、但尚未进入记忆档案的信件。

实时回信与拟合测试使用同一套四步 harness：预检关系与亲密上限、生成初稿、逐栏检查、仅在违规时反馈重写。检查通过时直接采用初稿；安全预检拦截或任一步报错时，信件进入失败状态。

管理窗口可保存 DeepSeek API Key。未勾选“自定义模型与地址”时使用默认 DeepSeek 配置；勾选后可指定兼容接口的模型名和地址。“测试 DeepSeek 连通性”可直接测试当前填写值。

也可以进入 `local-service` 后运行：

```powershell
npm start
npm test
```

```powershell
npm run build:win
```

每次执行 `build:win` 都使用固定版本号 `2008.2.7`。构建会编译 x64 WinForms 宿主，下载并校验固定版本的 Node.js、FFmpeg、whisper.cpp 与 Whisper small 模型，内置微软 WebView2 在线引导程序，再用 Inno Setup 生成安装包。结果输出到工作区 `build/`，安装包和便携版压缩包都包含语音模型，可直接分发并在首次转写时离线使用。发布白名单不包含开发目录中的私密信件、密钥、数据库、官方登录缓存或抓包。

客户端挂载会改写 `/signIn`、`/getUserInfo` 和六个 `/letter/*` 请求；主页内容、聊天、MIDI 和壁纸仍使用原服务。管理窗口会显示“服务已挂载/服务未挂载”及客户端实际端口。

## 数据位置

- 用户数据根目录：`%APPDATA%\OliviaSoul\`
- SQLite 与生成临时文件：`%APPDATA%\OliviaSoul\data\`
- 正式档案：`%APPDATA%\OliviaSoul\workspace\信件往来\`
- DeepSeek 配置：`%APPDATA%\OliviaSoul\workspace\.cursor\secrets\deepseek.env`
- 桌面端口与所选 exe：`%APPDATA%\OliviaSoul\desktop-settings.json`
- 客户端原版备份：`%APPDATA%\OliviaSoul\client-backups\`
- Whisper 模型：随包位于安装目录 `runtime\whisper\`；中文安装路径兼容副本位于 `%APPDATA%\OliviaSoul\models\whisper\`
- WebView2 用户数据：`%APPDATA%\OliviaSoul\WebView2\`

密钥仅通过本机管理页读取和修改；默认以密码形式遮挡，可用输入框内的小眼睛切换可见性。

## 备份与恢复

停止应用后备份 `%APPDATA%\OliviaSoul\`。恢复时先退出托盘中的 Olivia Soul，再把该目录复制回原位置后重新启动。

若 SQLite 文件丢失，标准 Markdown 档案仍保留原始往来，但队列、失败原因、已读状态和当日配额无法从档案完整恢复。第一版导入在目标档案已存在时会拒绝覆盖，不会自动猜测合并。
